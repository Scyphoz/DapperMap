# DapperMap

**A lightweight, sophisticated and fully configurable Hytale minimap.**

DapperMap adds a live minimap to the Hytale HUD. It combines nearby terrain, a directional player locator, configurable markers and useful world information in one compact display. Players can tailor the minimap display through an in-game settings interface or commands, while server administrators can control the defaults and decide which options players may change.

## Highlights

- Live terrain minimap generated from Hytale world-map data
- Circular and square map styles
- North-up or player-facing rotation
- Adjustable zoom, map size, interface scale and texture resolution
- Freely positionable HUD with a movable information panel
- Player, creature, death and world-map markers
- Creature icons drawn from each creature's own model, including creatures added by other mods, with threat-coloured outlines (classic coloured dots are also available)
- Optional hostile-only creature filter
- Player head icons drawn from each player's own skin, with or without their helmet, that flash in the attacking colour when a player attacks you in PvP
- Optional BetterMap waypoint integration
- Coordinates, bearing, world time and biome readouts
- Fully configurable colours for the frame, text and marker categories
- Per-player settings with persistent storage
- Server-defined defaults for new and uncustomised players
- Permission-aware settings: blocked controls are disabled and greyed out
- Separate player and administrator command branches

## Integrations

DapperMap supports integration with the following mods:
- BetterMap - DapperMap will display markers generated by BetterMap.
- LuckPerms - The DapperMap permission structure supports configuration by LuckPerms.

## Using DapperMap

The minimap can be controlled in two ways:

1. Run `/dappermap settings` to use the in-game settings interface.
2. Use the individual `/dappermap` commands for direct changes.

Commands can also be written as `/minimap`, `/mm` or `/dm`.

Running any base DapperMap command (e.g. `/dappermap`) without any subcommand toggles the minimap on and off.

## Features

### Live terrain map

DapperMap renders the terrain around the player using Hytale's native world-map information. The map pans as the player moves and refreshes the terrain when the surrounding map data changes.

Players can configure:

- **Zoom radius:** Controls how many blocks around the player are visible, from 16 to 256 blocks.
- **Map size:** Changes the on-screen map size from 120 to 360 pixels.
- **Texture resolution:** Changes the internal rendered texture resolution from 256 to 1024 pixels. Higher values produce more detail but require more processing and network delivery.
- **Interface scale:** Scales the complete map and information display from 75% to 160% without changing the world area being shown.
- **Map shape:** Selects a circular or square minimap.

### Rotation and compass

DapperMap supports two orientation modes:

- **North up:** North remains at the top while the player locator rotates.
- **Player facing:** The map rotates with the player's view so the forward direction remains at the top.

The optional compass readout shows the player's current bearing and facing direction.

### Update speed

Four update-speed profiles are available:

| Profile | Map panning | Markers | Terrain checks | Terrain refresh |
| --- | ---: | ---: | ---: | ---: |
| Very Fast | 40 ms | 50 ms | 150 ms | 300 ms |
| Fast | 75 ms | 100 ms | 300 ms | 600 ms |
| Normal | 150 ms | 250 ms | 750 ms | 1,200 ms |
| Slow | 300 ms | 500 ms | 1,500 ms | 2,500 ms |

Faster profiles make movement and markers feel more responsive, but can take a toll on server performance if being used by many players. Slower profiles reduce how often the server checks and redraws minimap content.

### HUD positioning and information panel

The complete minimap can be positioned horizontally and vertically anywhere from 0% to 100% of the available screen area. The settings page provides quick placement controls as well as fine adjustment sliders.

The information panel can appear above, below, left or right of the map. Its text can be aligned left, centre or right.

Individual information rows can be enabled or disabled:

- **Coordinates:** Current world coordinates
- **Bearing:** Compass bearing and facing direction
- **World time:** Current Hytale world time in 12-hour or 24-hour format
- **Region:** Current biome or region name

### Player and creature markers

DapperMap can show nearby players and creatures as colour-coded markers. Player markers follow the same visibility rules as Hytale's world map: players the viewer has hidden, spectating players (unless the viewer is also spectating) and all players in worlds whose gameplay config hides players are not shown.

Creature markers are colour-coded by threat:

- Creatures actively attacking the player
- Other hostile creatures
- Neutral or retreating creatures
- Friendly creatures

#### Creature marker style

Creatures can be shown in one of two styles:

- **Icons (default):** Each creature is shown as a small picture of itself with a coloured outline in its threat colour. Creatures actively attacking the player pulse so they stand out.
- **Dots:** Each creature is shown as a dot in its threat colour.

Creature icons are drawn by the server from each creature's own model and textures, so creatures added by other mods and mod packs get icons too, and DapperMap does not ship any creature artwork. Most creatures show a three-quarter view of their head. Long, legless creatures such as fish, eels, whales and snakes are shown side-on so their outline is easy to recognise. If a creature's model cannot be drawn, its in-game portrait is used, and failing that a disc showing its initials. Each icon is built once per creature type and reused for every player. Icons grow with the map size so they stay readable on larger maps.

#### Player marker style

Other players can be shown in one of two styles:

- **Icons (default):** Each player is shown as a small picture of their own head, built from their skin (skin tone, face, eyes, hair and head cosmetics, including modded cosmetics), with an outline in the player marker colour. If a player's head cannot be drawn, a disc showing their initials is used.
- **Dots:** Each player is shown as a dot in the player marker colour.

**Player Icon Helmets** chooses whether icons show the helmet each player wears (**Shown**, default) or always their bare head (**Hidden**). A helmet is never shown when its wearer has chosen to hide it in game. Player markers always draw above creature markers, including hostile and attacking creatures.

When PvP is enabled in the world and another player attacks you, that player's marker switches to the attacking colour (icons pulse like attacking creatures). It returns to the player colour once that player has not attacked you for 15 seconds, or when they die. Dead players are not shown until they respawn.

Each player's icon is built once per look (skin and helmet) and shared by every viewer; it is rebuilt only when that player changes their skin or helmet.

#### Creatures shown

**All (default)** shows every nearby creature. **Hostile Only** shows only hostile creatures and creatures currently attacking the player; a normally neutral creature appears while it is attacking. Player markers are not affected by this filter. The filter applies to both icons and dots.

#### Creature limit and height

The number of visible creature markers is selectable as **16 (default), 32 or 64**, nearest first. In Hostile Only mode the limit is filled with the nearest hostile creatures, so nearby passive animals do not hide more distant threats. Player and integration markers do not use this creature limit.

Creature height detection can hide entities that are too far above or below the player. The vertical range is configurable from 4 to 256 blocks.

### Death markers

When enabled, DapperMap shows the death markers that Hytale records for the player in the current world, the same markers shown on the full world map. They are edge-tracked like other map markers. Hytale's world setting for displaying death markers is respected, and when BetterMap is installed its death-marker hide options apply too. The Death Markers colour tints these icons (the default keeps their original look).

### Hytale world-map markers

DapperMap can display supported markers from Hytale's native world map, including personal markers, shared markers, points of interest, spawn and respawn locations. Markers designed for edge tracking remain visible around the edge of the minimap when their location is outside the current view.

### BetterMap integration

If BetterMap is installed and detected, DapperMap can display that player's BetterMap waypoints and waypoint icons. The integration can be enabled or disabled independently for each player or in the administrator defaults.

The master integration, waypoint-marker and cave-terrain switches are separate. Cave terrain additionally requires BetterMap cave mode to be active for the player.

Waypoints respect BetterMap's own options for hiding personal or global waypoints, and each waypoint is shown only once. With the BetterMap integration and its waypoint-marker switch on, waypoints use BetterMap's icons; otherwise they are shown with the Hytale world-map markers (when those are enabled). BetterMap's player radar is not shown, because DapperMap draws players itself.

BetterMap is optional. DapperMap remains fully functional without it.

### Colour editor

The in-game colour editor provides a live preview and lets players customise:

- Map edge and compass ticks
- Panel border, heading and label colours
- DapperMap title and information text
- Player locator and other player markers (player dots and player icon outlines)
- Death markers
- Attacking, hostile, neutral and friendly creature markers (used for creature dots and creature icon outlines; the attacking colour also marks players who attack you in PvP)

Colours may also be changed through commands using hexadecimal `#RRGGBB` values or decimal RGB channels.

### In-game settings interface

The settings interface is divided into Display, Markers, Interface, Position and Colours sections. Changes can be previewed before they are applied.

If a player lacks permission for a setting, that control is disabled and displays **Permission denied**. Permission checks are also repeated on the server when changes are applied, so a hidden or forged UI event cannot alter a blocked setting.

### Player settings and administrator defaults

New players inherit the current administrator set defaults. Simply joining does not create a personal settings file, so players who have never customised DapperMap continue to receive future administrator-default changes.

Once a player changes and applies a setting, DapperMap saves a personal override for that player. Using **Reset to Defaults** in the settings page removes that override and resumes inheritance from the current administrator defaults.

Administrator defaults are stored separately from player preferences and can be managed through the admin settings page or the `/dappermap admin` command branch.

## Commands

The primary command is `/dappermap`.

Aliases: `/minimap`, `/mm`, `/dm`

All DapperMap commands require a live player context because they operate on a player's HUD or open an in-game page. Administrator commands are therefore run in-game by an authorised player rather than from the dedicated server console.

### General commands

| Command | Description |
| --- | --- |
| `/dappermap` | Toggle the minimap |
| `/dappermap settings` | Open the player settings page |
| `/dappermap colours` | Open the colour editor |
| `/dappermap on` | Show the minimap |
| `/dappermap off` | Hide the minimap |
| `/dappermap help` | List command syntax and accepted values |
| `/dappermap status` | Show the current settings |
| `/dappermap reset` | Reset the player's values to the current server (administrator) defaults, the same as **Reset to Defaults** in the settings page |

### Display and placement commands

| Command | Description |
| --- | --- |
| `/dappermap zoom close\|medium\|far\|<16..256>` | Set the visible map radius; presets are 48, 96 and 160 blocks |
| `/dappermap size <120..360>` | Set the logical on-screen map size |
| `/dappermap scale <75..160>` | Scale the complete minimap interface |
| `/dappermap resolution <256..1024>` | Set the rendered map texture resolution |
| `/dappermap speed very-fast\|fast\|normal\|slow` | Select an update-speed profile |
| `/dappermap shape circle\|square` | Select the map shape |
| `/dappermap rotation north\|player` | Select north-up or player-facing rotation |
| `/dappermap position <x 0..100> <y 0..100>` | Position the complete HUD |
| `/dappermap info on\|off` | Show or hide the complete information panel |
| `/dappermap panel below\|above\|left\|right` | Position the information panel relative to the map |
| `/dappermap panel-alignment left\|centre\|right` | Align information-panel text (`center` is also accepted) |

### Marker and information commands

| Command | Description |
| --- | --- |
| `/dappermap markers players\|entities\|death\|worldmap on\|off` | Enable or disable a marker category |
| `/dappermap creature-markers icons\|dots` | Show creatures as icons (default) or dots (`creature-icons`, `creature-style` aliases) |
| `/dappermap creature-filter all\|hostile` | Show all creatures (default) or only hostile and attacking ones (`creatures-shown`, `hostile-only` aliases) |
| `/dappermap player-markers icons\|dots` | Show other players as head icons (default) or dots (`player-icons`, `player-style` aliases) |
| `/dappermap player-helmets shown\|hidden` | Show helmets on player icons (default) or always show the bare head (`player-helmet`, `helmets` aliases) |
| `/dappermap creature-limit 16\|32\|64` | Set the maximum visible creature markers |
| `/dappermap height on\|off` | Enable or disable creature height filtering |
| `/dappermap height-range <4..256>` | Set the allowed creature distance above and below the player |
| `/dappermap coordinates on\|off` | Show or hide coordinates |
| `/dappermap compass on\|off` | Show or hide Bearing (`bearing` alias) |
| `/dappermap clock on\|off\|12\|24` | Control World Time and Clock Format (`world-time` alias) |
| `/dappermap biome on\|off` | Show or hide Region (`region` alias) |
| `/dappermap integration native on\|off` | Control Hytale world-map markers |
| `/dappermap integration bettermap enable\|disable` | Control the BetterMap master integration |
| `/dappermap integration bettermap markers on\|off` | Control BetterMap waypoint markers |
| `/dappermap integration bettermap caves on\|off` | Control cave terrain; BetterMap cave mode must already be active |

### Colour commands

| Command | Description |
| --- | --- |
| `/dappermap colours list` | List available colour targets and their current values |
| `/dappermap colour <target> <#RRGGBB>` | Set a colour using hexadecimal RGB |
| `/dappermap colour <target> <R G B>` | Set a colour using decimal RGB channels from 0 to 255 |
| `/dappermap colour reset <target>` | Reset one colour target |
| `/dappermap colour reset all` | Reset the complete palette |

### Administrator commands

The administrator branch uses the same settings and values as the player branch, but changes the defaults inherited by new and uncustomised players.

```text
/dappermap admin settings
/dappermap admin status
/dappermap admin help
/dappermap admin reset
/dappermap admin <setting> <value>
```

Examples:

```text
/dappermap admin zoom far
/dappermap admin shape circle
/dappermap admin markers entities off
/dappermap admin clock 24
/dappermap admin panel-alignment centre
/dappermap admin creature-limit 32
/dappermap admin creature-markers dots
/dappermap admin creature-filter hostile
/dappermap admin player-helmets hidden
/dappermap admin integration bettermap enable
```

`/dappermap admin settings` opens the administrator version of the settings interface. Administrator mode is governed only by the admin permission and does not require each player-setting permission.

## Permissions

DapperMap keeps player permissions and administrator access in separate branches:

```text
scyphoz.dappermap.command.<setting>
scyphoz.dappermap.admin
```

This separation means that granting every player command with `scyphoz.dappermap.command.*` never grants access to administrator settings.

### Default permission behaviour

The `GrantPlayerSettingsByDefault` value in `dappermap_minimap.json` controls how player permissions are registered.

#### Player settings enabled by default

```json
"GrantPlayerSettingsByDefault": true
```

This is the default mode. Every player command and setting permission is granted through Hytale's default player group. Server administrators can selectively block features by explicitly denying their permission nodes through Hytale's permission system or a compatible provider such as LuckPerms.

An explicit denial also disables and greys out the corresponding setting in the in-game interface.

#### Explicit grants required

```json
"GrantPlayerSettingsByDefault": false
```

In this mode, DapperMap registers the permission nodes without granting them to the default player group. Players receive only the commands and settings that the administrator explicitly grants.

After changing `GrantPlayerSettingsByDefault`, restart the server so DapperMap can register its permissions using the new policy.

For access to the graphical settings page, grant:

```text
scyphoz.dappermap.command.settings
```

Then grant the permissions for the controls that the player may use. To allow every player-facing command and setting at once, grant:

```text
scyphoz.dappermap.command.*
```

To allow only the bare `/dappermap` toggle, grant:

```text
scyphoz.dappermap.command.toggle
```

| `scyphoz.dappermap.command.zoom` | Zoom radius |
| `scyphoz.dappermap.command.size` | Map size |
| `scyphoz.dappermap.command.scale` | Interface scale |
| `scyphoz.dappermap.command.resolution` | Texture resolution |
| `scyphoz.dappermap.command.speed` | Update speed |
| `scyphoz.dappermap.command.shape` | Circle or square map shape |

`help` uses `scyphoz.dappermap.command.help`. New direct commands intentionally reuse the permissions of their matching UI controls: `panel-alignment` uses `panel`, and `creature-limit`, `creature-markers`, `creature-filter`, `player-markers` and `player-helmets` use `markers`. Info Panel visibility uses `scyphoz.dappermap.command.info`.

Command aliases use the permission assigned to their canonical command. For example, `coords` uses the `coordinates` permission and `update` uses the `speed` permission.

### Administrator permission

Administrator access is controlled by one separate permission:

```text
scyphoz.dappermap.admin
```

This permission allows an in-game player to:

- Open `/dappermap admin settings`
- View and change all server-default settings
- Use every `/dappermap admin <setting>` subcommand
- Reset administrator defaults to the mod defaults

The admin permission is granted to Hytale's operator group by default. If another permission provider is installed, the same node can be granted or denied through that provider.

Granting `scyphoz.dappermap.command.*` does **not** grant `scyphoz.dappermap.admin`.

## Bootstrap configuration

The main `dappermap_minimap.json` file contains the initial mod-level defaults:

| Setting | Default | Description |
| --- | ---: | --- |
| `EnabledByDefault` | `true` | Whether the minimap starts enabled before administrator or player overrides are applied |
| `DefaultRadiusBlocks` | `96` | Initial zoom radius |
| `ShowCoordinates` | `true` | Initial coordinate-readout state |
| `GrantPlayerSettingsByDefault` | `true` | Whether player permissions are granted through Hytale's default player group |

The administrator settings page provides the full set of operational defaults. These are stored independently from the bootstrap configuration.
